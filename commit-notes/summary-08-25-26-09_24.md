## Overview

This commit introduces live external website connectivity, an authenticated log ingestion API pipeline, and initial log feed hydration.

Key capabilities introduced:
1. **Connected Sites Schema & Storage**: A new `connected_sites` PostgreSQL table storing linked domains, user associations, API keys, and connection health ping timestamps.
2. **Site Management Endpoints**: Endpoints (`/api/site/config`, `/api/site/connect`, `/api/site/disconnect`) allowing users to link external project domains, generate/manage API keys, and broadcast status events via WebSockets.
3. **External Log Ingestion API**: A high-throughput `POST /api/ingest` endpoint that validates API keys (`X-API-Key` or `?api_key=...`), enforces offline connection gating (dropping logs if a site is disconnected), persists incoming logs to PostgreSQL, and broadcasts real-time socket events to connected dashboards.
4. **Live Feed Hydration**: A new `GET /api/logs/recent` endpoint fetching recent log history on initial page load or browser refresh.
5. **Connect Website Modal**: A modal dialog (`ConnectWebsiteModal.tsx`) with domain management, API key generator, test ping verification, and multi-language integration code snippets (**cURL**, **JavaScript / Node.js**, and **Python / FastAPI**).
6. **Live Feed Enhancements**: The `LiveLogFeed` component now prepends newest incoming logs at the top and respects offline status gating.

## Impact

* **Real-Time External Ingestion**: Allows external web apps, microservices, and APIs to stream HTTP logs directly to GoLog without manual file uploads.
* **Stream Gating & Control**: Disconnecting a site immediately blocks and drops incoming ingestion payloads at the API layer.
* **Persistent Feed History**: Hydrates recent logs upon page reload while respecting session clear preferences (`sessionStorage.getItem("golog_feed_cleared_at")`).
