## Overview

This commit resolves a JSON parsing bug caused by WebSocket frame batching, introduces static snapshot freezing for the frontend live log feed, enables relaxed CORS options for external client connections, and expands the `/api/simulate` endpoint with custom payload parameters.

On the backend, `WritePump` was previously concatenating buffered socket messages into a single text frame separated by newlines, causing client-side `JSON.parse()` calls to fail when multiple log messages arrived in quick succession. `WritePump` now writes each buffered message as an individual text frame.

On the frontend, the `LiveLogFeed` component now captures a frozen array snapshot (`frozenLogs`) when Pause is toggled, preventing incoming background logs from shifting the viewport. In addition, `useWebSocket.ts` incorporates line-splitting failsafes before parsing incoming JSON messages.

## Code Changes

### Backend WebSocket Individual Frame Emitting
In [internal/hub.go](file:///home/kienpham07/Downloads/Disk%20D%20Window/My%20project%2010%20-%20Web%20Log%20Analyzer/backend/internal/hub.go), `WritePump` replaces multi-write frame batching with individual frame emissions:
```go
case message, ok := <-c.Send:
	c.Conn.SetWriteDeadline(time.Now().Add(writeWait))
	if !ok {
		c.Conn.WriteMessage(websocket.CloseMessage, []byte{})
		return
	}

	if err := c.Conn.WriteMessage(websocket.TextMessage, message); err != nil {
		return
	}

	// Drain buffered send messages as individual text frames
	n := len(c.Send)
	for i := 0; i < n; i++ {
		c.Conn.SetWriteDeadline(time.Now().Add(writeWait))
		if err := c.Conn.WriteMessage(websocket.TextMessage, <-c.Send); err != nil {
			return
		}
	}
```
