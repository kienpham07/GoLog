## Overview

This commit addresses timezone offset shifts in log timestamp parsing, database retrieval, upload responses, and frontend displays.

Previously, log timestamps parsed during file ingestion or queried from PostgreSQL were susceptible to implicit local timezone conversions, causing log entries (e.g. generated on July 10 UTC) to shift forward or backward depending on the local timezone of the server or browser. 

The updated codebase enforces explicit UTC conversions across the backend parsing pipeline and uses UTC options (`{ timeZone: "UTC" }`) for frontend date formatting helpers.

### Frontend UTC Formatting Helpers
In [page.tsx](file:///home/kienpham07/Downloads/Disk%20D%20Window/My%20project/Project%2010%20-%20Web%20Log%20Analyzer/frontend/app/page.tsx), chart X-axis ticks specify UTC formatting:
```typescript
const formatHour = (tick: any) => {
  try {
    const d = new Date(tick);
    return d.toLocaleDateString("en-US", { month: "short", day: "numeric", timeZone: "UTC" }) + 
           " " + 
           d.toLocaleTimeString("en-US", { hour: "2-digit", minute: "2-digit", hour12: false, timeZone: "UTC" });
  } catch {
    return String(tick);
  }
};
```

A dedicated helper `formatUTCTimestamp` formats error log timestamps:
```typescript
const formatUTCTimestamp = (timestamp: string) => {
  try {
    const d = new Date(timestamp);
    if (isNaN(d.getTime())) return timestamp;
    return d.toLocaleString("en-US", {
      timeZone: "UTC",
      year: "numeric",
      month: "2-digit",
      day: "2-digit",
      hour: "2-digit",
      minute: "2-digit",
      second: "2-digit",
      hour12: false,
    }) + " UTC";
  } catch {
    return timestamp;
  }
};
```
The Error Logs table displays formatted UTC timestamps:
```typescript
<td className="py-3 font-mono text-gray-400">
  {formatUTCTimestamp(log.timestamp)}
</td>
```
