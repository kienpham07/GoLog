## Overview

This commit adds a client-side login/register experience for the GoLog frontend and connects the dashboard to the existing backend JWT authentication flow. The dashboard now checks for a saved JWT before fetching log data, redirects unauthenticated users to `/login`, attaches the token to `/api/logs` requests, and provides a logout control that clears the local token.

The supporting backend and deployment changes make this browser flow possible:

- CORS now allows the `Authorization` header so the frontend can send `Bearer` tokens to the Go API.
- Docker Compose now passes `JWT_SECRET` into the backend container, which is required by the existing JWT initialization code.
- Root-level npm metadata and `node_modules` were added for React packages, although the active Next.js app already has its own `frontend/package.json`.

The main problem solved is that authentication is no longer only available through backend endpoints. Users now have a browser UI for registration/login, and the dashboard can behave like a protected page instead of blindly requesting logs.

## Files Changed

### Application Source and Configuration

- **Modified `backend/cmd/main.go`**  
  Adds `Authorization` to the allowed CORS headers. This is required because authenticated dashboard requests now send `Authorization: Bearer <token>` from the browser. Without this header in the CORS configuration, browsers would block cross-origin frontend requests to the Go backend during preflight validation.

- **Modified `docker-compose.yml`**  
  Passes `JWT_SECRET` into the backend service environment. The backend calls `utils.InitJWT()` during startup, and that function exits the process if `JWT_SECRET` is missing. This change makes containerized runs compatible with the JWT requirement.

- **Added `frontend/app/login/page.tsx`**  
  Introduces a new Next.js client page at `/login`. The page contains a combined login/register form, posts credentials to `/api/login` or `/api/register`, stores the returned JWT in `localStorage` as `golog_token`, and redirects successful logins to the dashboard.

- **Modified `frontend/app/page.tsx`**  
  Converts the dashboard into a token-aware client flow. It checks `localStorage` for `golog_token`, redirects missing or unauthorized sessions to `/login`, fetches logs with a bearer token, and adds a logout button that clears the token.

- **Added `package.json`**  
  Adds a root-level npm manifest with `react`, `react-dom`, `@types/react`, and `@types/react-dom`. This appears to come from running npm at the repository root rather than inside `frontend`. The active frontend package remains `frontend/package.json`, which already defines Next.js, React, Recharts, Tailwind, TypeScript, and lint dependencies.

- **Added `package-lock.json`**  
  Adds a root-level npm lockfile for the new root package. It locks React `19.2.7`, React DOM `19.2.7`, React type packages, `csstype`, and `scheduler`. This lockfile corresponds to the root `package.json`, not the existing `frontend/package.json`.

## Code Changes

### Login and Registration Page

`frontend/app/login/page.tsx` is a client component because it uses React state, browser storage, and Next.js client navigation:

```tsx
"use client";
```

The page tracks whether the user is logging in or registering through `isLogin`. A single `handleSubmit` function chooses the endpoint based on that state:

```tsx
const endpoint = isLogin ? "/api/login" : "/api/register";
```

Important behavior:

- Sends JSON credentials to the backend using `fetch`.
- Uses `NEXT_PUBLIC_API_URL` when available and falls back to `http://localhost:8080`.
- Parses backend JSON defensively and reports invalid server responses.
- Stores successful login tokens as `localStorage["golog_token"]`.
- Redirects successful logins to `/`.
- Switches back to login mode after registration and prompts the user to sign in.
- Clears the password after failed submissions and after successful registration.
- Disables form controls while a request is in progress to avoid duplicate submissions.

### Dashboard Authentication Check

`frontend/app/page.tsx` now imports `useRouter` and performs an auth check before loading logs:

```tsx
const token = localStorage.getItem("golog_token");
if (!token) {
  router.push("/login");
  return;
}
```

When a token exists, the dashboard sends it to the backend:

```tsx
headers: {
  Authorization: `Bearer ${token}`,
}
```

If the backend returns `401`, the frontend treats the token as invalid or expired, removes it from local storage, and sends the user back to `/login`. This avoids keeping users on a dashboard that can no longer retrieve protected data.

### Logout Flow

The dashboard adds `handleLogout`, which clears `golog_token` and navigates to `/login`. The UI places a `Logout` button next to the dashboard title. This gives users a direct way to end the local session without manually clearing browser storage.

### CORS Header Support

The backend CORS configuration now allows `Authorization`:

```go
AllowHeaders: []string{"Origin", "Content-Type", "Accept", "Authorization"}
```

This is a small but necessary integration point. Browser-based JWT authentication fails if preflight requests do not allow the custom authorization header.

### Docker Environment

`docker-compose.yml` now passes:

```yaml
JWT_SECRET: ${JWT_SECRET}
```

The backend requires this variable at startup, so deployments must provide it through the shell environment or an `.env` file consumed by Docker Compose.

### Dependency and Repository Structure Notes

The root-level `package.json`, `package-lock.json`, and committed `node_modules` contents introduce a second JavaScript package context at the repository root. The Next.js app still lives under `frontend`, and `frontend/package.json` already has its own dependency set. Future maintainers should decide whether the root package is intentional. If it is not intentional, the cleaner project structure is usually:

- keep frontend dependencies in `frontend/package.json`;
- keep `frontend/package-lock.json` or the chosen package manager lockfile in `frontend`;
- exclude `node_modules/` from Git using `.gitignore`;
- recreate dependencies with `npm install` rather than committing installed package files.

## Impact

- Users can now register and log in from the browser instead of calling auth endpoints manually.
- The dashboard behaves as a protected page from the frontend perspective. Users without `golog_token` are redirected to `/login`.
- Dashboard log requests now include a bearer token, preparing the frontend for protected backend routes.
- The backend accepts browser requests that include `Authorization`, fixing a required CORS preflight condition for token-based API calls.
- Docker-based backend startup now depends on a configured `JWT_SECRET`.

### Breaking Changes and Deployment Considerations

- **`JWT_SECRET` is required.** The backend calls `utils.InitJWT()` and exits if the variable is missing. Docker Compose deployments must define `JWT_SECRET`.
- **Frontend API URL configuration matters.** The frontend uses `NEXT_PUBLIC_API_URL` when set and otherwise calls `http://localhost:8080`. Non-local deployments should set `NEXT_PUBLIC_API_URL` to the public backend URL.
- **Token storage is local to the browser.** The frontend stores JWTs in `localStorage`. This is straightforward for a project dashboard, but future production hardening should consider XSS risk and whether an HTTP-only cookie flow is more appropriate.
- **Backend `/api/logs` still needs verification.** In the current source tree, `/api/logs` accepts the request but does not validate the bearer token in `backend/cmd/main.go`. The frontend sends the token and handles `401`, but the backend route must enforce JWT validation for true server-side access control.
- **Repository size and dependency hygiene are affected.** Committing `node_modules` adds a large number of generated files. This can slow clones, diffs, and reviews. The root `package.json` also uses React `19.2.7`, while `frontend/package.json` uses React `19.2.4`, so maintainers should avoid accidentally running the wrong package context.
