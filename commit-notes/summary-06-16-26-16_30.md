## Overview

The recent changes focus on transitioning the project from hardcoded configurations to a robust, environment-driven setup while significantly hardening the application's security posture. Key improvements include implementing file upload constraints, securing network exposure in Docker, and refactoring database connectivity to be more flexible and secure.

---

## Files Changed

### Backend Core
- **`backend/cmd/main.go`**: Implemented request size limits and file upload validation. Refactored upload logic to handle large file errors gracefully.
- **`backend/database/db.go`**: Completely refactored the connection logic. Replaced hardcoded connection strings with dynamic DSN construction using environment variables. Added helper functions for environment variable management.

### Configuration & Infrastructure
- **`docker-compose.yml`**: Updated to use environment variables for database credentials. Restricted port mappings to `127.0.0.1` to prevent unauthorized external access. Enhanced service dependency and healthcheck logic.
- **`.env.example`**: Created to provide a template for local environment configuration without exposing real secrets.
- **`.gitignore`**: Updated to ensure `.env` files are never accidentally committed to the repository.

---

## Code Changes

### Security Hardening in Uploads
The backend now enforces strict limits on file uploads to prevent Denial of Service (DoS) attacks via disk exhaustion or memory overflow.
```go
const (
    maxUploadSize      int64 = 8 << 20                   // 8MB limit for the file itself
    maxRequestBodySize int64 = maxUploadSize + (1 << 20) // 9MB limit for the total request
)

// Inside the upload handler:
c.Request.Body = http.MaxBytesReader(c.Writer, c.Request.Body, maxRequestBodySize)
```
- Added `http.MaxBytesReader` to terminate large requests early.
- Explicitly checks `file.Size` before processing.

### Robust Database Configuration
The database connection logic was upgraded from simple string formatting to a structured URL-based approach.
- **DSN Construction**: Uses `net/url` to safely encode credentials and parameters, preventing issues with special characters in passwords.
- **Environment Helpers**: 
    - `requiredEnv(key)`: Crashes the app early if critical configuration is missing.
    - `optionalEnv(key, default)`: Provides sensible defaults for non-critical settings.
- **SSL Mode Support**: Introduced `DB_SSLMODE` (defaulting to `disable`) to allow secure connections in production environments.

### Docker Network Security
Port mappings in `docker-compose.yml` were modified to bind specifically to the loopback interface:
- `127.0.0.1:8080:8080` (Backend)
- `127.0.0.1:3000:3000` (Frontend)
This ensures that the services are only accessible from the host machine and not from the public internet or local network unless explicitly configured otherwise.

## Impact

- **Breaking Change**: The application now *requires* environment variables to start. Developers must copy `.env.example` to `.env` and fill in their local values.
- **Security**: Significantly reduced attack surface for file uploads and database access.
- **Deployment**: The infrastructure is now ready for different environments (Dev, Staging, Prod) by simply swapping environment variables.

## Testing

### Manual Testing Recommended
1. **Upload Size Limit**: Attempt to upload a file larger than 8MB. The server should return a `413 Request Entity Too Large` error.
2. **Environment Validation**: Try running the application without a `.env` file or missing variables. It should fail with a clear error message.
3. **Database Connectivity**: Verify that the application successfully connects to Postgres using the credentials provided in the `.env` file.
4. **Network Exposure**: Verify that the services are not accessible via the host's external IP address.
