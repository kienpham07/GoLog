## Overview

This commit introduces a major architectural upgrade to the Web Log Analyzer (GoLog) application. It transitions the core logic from basic client-side dynamic evaluation to a robust, database-driven analytics engine. The database schema has been restructured to support **Log Upload Sessions**, tracking metadata like user associations, upload sessions, and parsed vs. skipped lines. 

To power the dashboard with pre-aggregated statistics, the backend exposes **8 new analytical endpoints** (overview, traffic time buckets, top endpoints, top IPs, HTTP status codes, browser categorization, and error logs with offset pagination). Safety improvements include a strict **5-upload-per-hour rate limit** per user and MIME-type/extension verification for uploaded files.

## Code Changes

### Comprehensive Log Model & Parser Upgrades
The log ingestion service in [parser.go](file:///home/kienpham07/Downloads/Disk%20D%20Window/My%20project/Project%2010%20-%20Web%20Log%20Analyzer/backend/services/parser.go) now parses the Apache Combined Log Format:
```go
logPattern := regexp.MustCompile(`^(\S+)\s+\S+\s+\S+\s+\[([^\]]+)\]\s+"(\S+)\s+(.*?)\s+(\S+)"\s+(\d+)\s+(\d+|-)\s+"([^"]*)"\s+"([^"]*)"\s+(\d+)$`)
```
This regex captures:
1. `ip` (client IP address)
2. `timestamp` (parsed via `02/Jan/2006:15:04:05 -0700`)
3. `method` (HTTP request method)
4. `endpoint` (requested URI path)
5. `protocol` (HTTP version)
6. `status` (HTTP status code integer)
7. `bytes` (response size in bytes, defaulting `-` to `0`)
8. `referrer` (HTTP referrer URL)
9. `user_agent` (user agent string)
10. `response_time` (response processing latency in milliseconds)

### Ingestion Session Management and Rate Limiting
During log ingestion in [main.go](file:///home/kienpham07/Downloads/Disk%20D%20Window/My%20project/Project%2010%20-%20Web%20Log%20Analyzer/backend/cmd/main.go), upload requests pass through the following validations:
* **MIME & Extension Security**: Only files with a `.log` extension and a `text/plain` or text-prefixed Content-Type are accepted.
* **Rate Limiting**: Users are capped at **5 uploads per hour**, checking database logs via `GetUploadCountInLastHour(userID)`:
```go
count, err := database.GetUploadCountInLastHour(user.ID)
if count >= 5 {
    c.JSON(http.StatusTooManyRequests, gin.H{"error": "Rate limit exceeded. Maximum 5 uploads per hour allowed."})
    return
}
```
* **Session Tracking**: Successfully parsed uploads create a session record inside the `sessions` table mapping the user ID, source filename, parsed count, and skipped lines. The session's auto-generated ID is bound to all associated log records.

### Context Propagation in Middleware
The JWT bouncer in [auth.go](file:///home/kienpham07/Downloads/Disk%20D%20Window/My%20project/Project%2010%20-%20Web%20Log%20Analyzer/backend/middleware/auth.go) propagates username details to request context values:
```go
if claims, ok := token.Claims.(jwt.MapClaims); ok {
    if username, ok := claims["username"].(string); ok {
        c.Set("username", username)
    }
}
```
This enables subsequent handlers to retrieve the active user profile via `c.GetString("username")`.

### Session-Aware Database Schema and Performance Indexes
[db.go](file:///home/kienpham07/Downloads/Disk%20D%20Window/My%20project/Project%2010%20-%20Web%20Log%20Analyzer/backend/database/db.go) provisions the expanded storage schema:
```sql
CREATE TABLE IF NOT EXISTS sessions (
    id SERIAL PRIMARY KEY,
    user_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
    filename TEXT NOT NULL,
    parsed_count INTEGER NOT NULL,
    skipped_count INTEGER NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```
Additionally, performance indexes (`idx_logs_timestamp`, `idx_logs_status`, `idx_logs_ip`, `idx_logs_session_id`) speed up execution of grouping and aggregate queries.

### Backend-Driven Aggregated Stats Endpoints
[repository.go](file:///home/kienpham07/Downloads/Disk%20D%20Window/My%20project/Project%2010%20-%20Web%20Log%20Analyzer/backend/database/repository.go) implements database-level aggregation queries that take an optional `session_id` filter:
1. **`GET /api/stats/overview`**: Calculates aggregates (total requests, unique visitors, error rates, and total bandwidth).
2. **`GET /api/stats/traffic`**: Time-buckets request occurrences into timestamp-rounded intervals.
3. **`GET /api/stats/top-endpoints`**: Computes request metrics grouped by endpoint path.
4. **`GET /api/stats/top-ips`**: Ranks request volumes from client IPs.
5. **`GET /api/stats/status-codes`**: Aggregates the quantity of HTTP responses grouped by status code.
6. **`GET /api/stats/browsers`**: Categorizes user agent headers (Chrome, Firefox, Safari, Edge, Safari, Mobile, or Other).
7. **`GET /api/logs/errors`**: Retrieves client and server error entries (status `>= 400`) supporting limit/offset pagination.

## Impact

* **Performance Optimization**: Dynamic calculations are moved to PostgreSQL database aggregates, reducing memory overhead on the client.
* **Granular Filters**: Dashboard users can view unified stats across all uploads, or filter analytics by choosing a specific ingestion session.
* **Secured Operations**: Protects backend services against Denial of Service attempts by enforcing upload limits and MIME filters.
* **Precise Diagnostics**: Allows pagination of raw error logs to inspect client/server failures quickly.
