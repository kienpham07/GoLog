## Code Changes

### Authentication Implementation
*   **JWT Token Management:** A new utility (`backend/utils/jwt.go`) handles the initialization of the secret key and the generation of tokens. Tokens are signed using `HS256` and have a 24-hour expiration.
*   **Password Hashing:** User passwords are now hashed using `bcrypt` with a cost factor of 14 before being stored in the database, ensuring that plain-text passwords are never saved.
*   **New Endpoints:**
    *   `POST /api/register`: Validates input, hashes the password, and creates a new user record.
    *   `POST /api/login`: Verifies credentials against the database and returns a signed JWT.

### Database Security & Schema
*   **Prepared Statements:** All database operations in `repository.go` now use prepared statements. This prevents SQL injection attacks and improves performance for repeated queries.
*   **User Schema:** The `InitSchema` function was expanded to create a `users` table with a unique constraint on the `username` field.

### Infrastructure & Security
*   **Docker Hardening:** In `docker-compose.yml`, ports for the backend (`8080`) and frontend (`3000`) are now bound to `127.0.0.1`. This ensures that the services are only accessible through a local proxy or SSH tunnel, reducing the attack surface.
*   **Service Dependencies:** The backend service now waits for the database to pass a health check before starting, preventing connection failures during boot.

## Impact

*   **Authentication Required:** Future features can now be protected by requiring a valid JWT in the `Authorization` header.
*   **Breaking Changes:** None for existing public endpoints, but the database now requires a `users` table which is automatically created on startup.
*   **Deployment:** The `.env` file must now include a `JWT_SECRET` (at least 32 characters recommended) for the application to start.
