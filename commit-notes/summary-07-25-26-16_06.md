## Overview

This commit refactors the security threat classification logic for client IP addresses in both the backend database query layer and the frontend dashboard table. 

Previously, the backend used a simplistic `COUNT(*) > 200` check combined with basic string equality checks against sensitive paths. The updated implementation uses SQL Common Table Expressions (CTEs) to evaluate multi-factor security threat criteria: sensitive endpoint path probing, authorization failure spikes (`401 Unauthorized`), volumetric traffic caps (`600+` requests), and statistical anomalies relative to average traffic per IP. On the frontend, non-suspicious IP status badges have been updated from `"Clean"` to `"Normal"`.

## Code Changes

### Multi-Criteria SQL CTE for IP Risk Evaluation
In [repository.go](file:///home/kienpham07/Downloads/Disk%20D%20Window/My%20project/Project%2010%20-%20Web%20Log%20Analyzer/backend/database/repository.go), `GetTopIPs` replaces direct SELECT statements with CTE aggregation queries:
```sql
WITH ip_counts AS (
    SELECT 
        ip, 
        COUNT(*) as cnt,
        SUM(CASE 
            WHEN LOWER(endpoint) LIKE '%/.env%' 
              OR LOWER(endpoint) LIKE '%.env%'
              OR LOWER(endpoint) LIKE '%/wp-admin%'
              OR LOWER(endpoint) LIKE '%/wp-login.php%'
              OR LOWER(endpoint) LIKE '%/phpmyadmin%'
              OR LOWER(endpoint) LIKE '%/.git%'
              OR LOWER(endpoint) LIKE '%/config%'
            THEN 1 ELSE 0 
        END) as sensitive_cnt,
        SUM(CASE WHEN status = 401 THEN 1 ELSE 0 END) as auth_fail_cnt
    FROM logs
    GROUP BY ip
),
stats AS (
    SELECT COALESCE(AVG(cnt), 0) as avg_cnt FROM ip_counts
)
SELECT 
    i.ip, 
    i.cnt,
    (i.sensitive_cnt > 0 OR i.auth_fail_cnt > 10 OR i.cnt > 600 OR (i.cnt >= (SELECT avg_cnt * 2.0 FROM stats) AND i.cnt >= 50)) as suspicious
FROM ip_counts i
ORDER BY i.cnt DESC
LIMIT 10
```

### Risk Evaluation Criteria
An IP address is flagged as `suspicious` if it meets any of the four rules:
1. **Sensitive Path Probing** (`sensitive_cnt > 0`): Any requests targeting `.env`, `.git`, `wp-admin`, `wp-login.php`, `phpmyadmin`, or `config` files.
2. **Auth Failure Spike** (`auth_fail_cnt > 10`): More than 10 `401 Unauthorized` responses (indicating brute-force or credential stuffing attempts).
3. **Volumetric Flood** (`cnt > 600`): Excessive request traffic from a single origin IP.
4. **Statistical Anomaly** (`cnt >= avg_cnt * 2.0 AND cnt >= 50`): Traffic exceeding double the average request count per IP across the dataset (with a minimum floor of 50 requests).

## Impact

* **Accurate Threat Detection**: Catches stealthy probe scans (e.g. 1-2 requests targeting `.env` or `.git`) and brute-force login attempts (`401` spikes) that were missed by simple request volume thresholds.
* **Statistical Intelligence**: Dynamically adapts volumetric thresholding to dataset averages rather than relying only on a single hardcoded number.
* **Standardized Status Vocabulary**: Replaces `"Clean"` with `"Normal"` in the UI for clearer security reports.
